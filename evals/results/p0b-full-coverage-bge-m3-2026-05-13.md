## 分析

### bge-m3 有改善的地方
- **手册7 均分从 0.33 → 0.417**：M7-3(跟踪/自动/PID) 和 M7-6(MOTCTRL/VALCTRL) 从之前的失败变为 Pass
- M7-5(旁路) 从 Fail → Partial

### bge-m3 仍然失败的地方
这些工程缩写/术语无论哪个嵌入模型都检索不到：
- **ADD/SUB/MUL/DIV** — 纯英文缩写，PDF中以表格行形式出现
- **PVU/PVL/ENGU/ENGL** — 特定领域缩写
- **SWITCH/ORSEL/MULDIV/SUMMER** — 高级运算块名
- **符号库/MOT/VAL** — 手册5的符号系统术语

### 根因
bge-m3 虽然是中文优化模型，但对**中文工程手册中的英文缩写 + 表格嵌入**场景的语义匹配仍然不足。这些术语在 PDF 中以参数表形式出现（如 "10 强制 0 否 否 是 否"），chunk 化后丢失了上下文关联。

## 结论

⚠️ 嵌入模型升级效果有限（0.45 → 0.50，+11%），未达到预期。手册7的核心痛点（英文缩写术语检索）依然存在。

**建议方向**：
1. 不继续换嵌入模型，转而从检索策略入手（关键词增强 + 术语词典扩展查询）
2. 对英文缩写术语做显式的 query expansion（如 ADD → "加法运算块"）
3. 考虑在 chunk 层面标注术语-定义关联
