## 支线主题

在支线A（跨分册主链，A1-A4 全绿收口）和支线B（定义+约束，B1-B4 全绿收口）之后，新增三类题型以覆盖 RAG 问答更广泛的风险面：

| 题型 | 核心测什么 | 风险面 |
|------|-----------|--------|
| **故障排查型** | answer 层面对故障场景时是否正确引用文档，不误套不相关模板 | answer 层误套流程模板（如把故障排查当成'流程步骤'问题回答） |
| **参数约束型** | 精确参数值召回和约束边界表述 | retrieval 层是否漏掉关键数字约束，answer 层是否精确引用 |
| **操作条件型** | 条件分支提取，TRUE/FALSE/场景判断 | answer 层是否展开条件分支，避免笼统回答 |

每类 3 题，共 9 题（N1-N9）。

## 停手条件

| 条件 | 动作 |
|------|------|
| 9/9 全绿 | ✅ 直接收口，新题型支线关闭 |
| 存在 partial/fail，但主因是 answer 层 | 记录为已知限制，允许最小 answer patch 后复跑 1 轮 |
| stable + 非answer主因(retrieval/ranking/chunk/parse) + ≥2题同类复现 | 登记 P0-B retrieval 候选（与 A1-A4 同流程） |
| 最多 2 轮 | 若仍有 fail 则分析主因并记录为已知限制 |

## 题目设计

### 题型1：故障排查型（N1-N3）

| ID | 问题 | 预期源 | 核心测点 |
|----|------|--------|---------|
| N1 | 工程编译时报错"编译失败"，可能是什么原因导致的？如何处理？ | 手册3 Ch5 编译 + 手册4 Ch16 常见问题 | 是否识别"故障排查"特征并引用常见问题章节，而非输出通用编译流程 |
| N2 | MACS V6.5 下装操作失败，提示"创建压缩文件失败，将导致OPS监视的逻辑与AT不一致"，如何排查和解决？ | 手册4 Ch16.15.5 常见问题 | 是否引用具体错误码对应的解决方案，而非笼统描述下装流程 |
| N3 | 在 AutoThink 中执行在线操作时提示"通讯失败"、无法连接控制器，如何排查问题？ | 手册4 Ch9 编译 + 手册4 Ch10 下装 | 是否区分通讯失败的不同原因（网段/在线模式/仿真限制），给出排查步骤 |

### 题型2：参数约束型（N4-N6）

| ID | 问题 | 预期源 | 核心测点 |
|----|------|--------|---------|
| N4 | MACS V6.5 一个现场控制站最多能支持多少个 I/O 点数？一个域最多能支持多少个控制站？不同型号控制器（K-CU01/K-CU02/K-CU03）的容量有什么区别？ | 手册3 Ch14.1 系统容量 | 精确数字召回（20,000/36,000 等），区分不同控制器型号 |
| N5 | 算法组态中，参数对齐设置为 TRUE 和 FALSE 分别代表什么含义？基本类型变量和 FB 类型变量的参数对齐有什么不同？ | 手册4 Ch6 变量 — 参数对齐 | TRUE/FALSE 分支展开，变量类型区分 |
| N6 | MACS V6.5 工程加密后，编译、下装、在线修改功能会受到哪些限制？加密的 POU 在打开时有什么要求？ | 手册4 Ch4.2 工程加密 + 手册6 现场操作 | 多操作影响召回（编译/下装/在线修改/打开），加密条件边界 |

### 题型3：操作条件型（N7-N9）

| ID | 问题 | 预期源 | 核心测点 |
|----|------|--------|---------|
| N7 | MACS V6.5 什么情况下需要进行全编译？全编译和增量编译各适用什么场景？触发全编译的条件有哪些？ | 手册3 Ch5 编译 + 手册4 Ch9 编译 | 全编译触发条件（首次编译/增删控制站/系统异常），两种编译方式对比 |
| N8 | MACS V6.5 增量编译的前提条件是什么？修改了哪些内容会触发增量编译？增量编译相比全编译有什么优势？ | 手册3 Ch5 编译 + 手册4 Ch9 编译 | 增量编译适用条件（无系统异常/特定修改类型），与全编译对比 |
| N9 | MACS V6.5 中，在线修改值 和 下装修改 各适用于什么场景？修改在线值后如果再次下装，在线值会被覆盖吗？ | 手册6 现场操作 + 手册4 Ch10/Ch11 | 在线 vs 下装两种修改方式的场景区分，参数对齐对在线值的影响 |
